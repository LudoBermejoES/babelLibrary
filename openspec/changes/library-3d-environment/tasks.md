> **TDD rule (applies to every task, per the `development-workflow` spec):** each task is red → green → refactor. Write the failing test(s) named in the task first, watch them fail, implement minimally, refactor green. A task may only be checked off with its layer's full suite passing. Where a task is exploratory (asset sourcing, lighting feel), its acceptance test is written the moment the exploration settles — before the checkbox.

## 3. Procedural layout generator (M2 — doc [04](../../../doc/04-wasm-generator.md))

> **Borges fidelity (D11 in design.md)**: this section was rewritten before implementation began, following direct research into Jorge Luis Borges' "The Library of Babel." Every hexagon has a fixed shape (4 shelf walls / 1 vestibule / 1 shaft, 160-book capacity — a deliberate reduction from Borges' 640, see doc 04's fidelity table), addressed in 3D `(q, r, floor)`, connected horizontally through vestibules and vertically through spiral staircases in those same vestibules.

- [x] 3.1 RED: write the native determinism suite first (doc 04 list), asserting against `gen/config.rs` constants (not literals — plus one `fidelity_defaults` test pinning the current defaults): identical output for same (seed, catalog); N books ⇒ N unique slots; seeds differ; hint wins; spine bounds; **fixed hexagon shape (`SHELF_WALLS_PER_HEX`/`SHELVES_PER_HEX`/`BOOKS_PER_HEX`/`LAMPS_PER_HEX` — defaults 4/20/160/2 — every gallery, regardless of position)**; graph connectivity across floors (horizontal + staircase edges); **floors fill before the next floor starts**; **vestibule stair flags match real floor neighbors**; ≥0.9 m vestibule-opening clearance; ≥7 galleries minimum on floor 0 — all failing against stub types (the `config.rs` constants module is written as part of this task, since the tests import it)
- [x] 3.2 GREEN: hex gallery-graph generation — floor 0 as one winding chain (seeded random walk, each hexagon connects only to the previous/next in the chain since it has exactly one vestibule wall) to a target length (7–19 hexagons), with the last hexagon looping back to the first (the concrete "unlimited but periodic" resolution — doc 04); then floor 1+ generated directly above filled floor-0 `(q, r)` positions once floor 0 reaches its target, repeating until `ceil(book_count / BOOKS_PER_HEX)` galleries exist — until graph/floor tests pass
- [x] 3.3 GREEN: fixed per-gallery furnishing driven by `config.rs` — always `SHELF_WALLS_PER_HEX` × `SHELVES_PER_WALL` × `SLOTS_PER_SHELF` slots (defaults 4 × 5 × 8 = 160), always `LAMPS_PER_HEX` crosswise lamps, always 1 vestibule (mirror + 2 closets + doorway/staircase flags reflecting real neighbors); no world-model numeric literal outside `config.rs` — until shape tests pass
- [x] 3.4 GREEN: book→slot assignment (fixed traversal order: floor ascending → gallery chain order → shelf-wall 0–3 → row → slot 0–7, over pre-sorted input; per-book dims/colors keyed by (seed, book id)) until assignment tests pass
- [x] 3.5 RED→GREEN: buffer-emission tests (stride/length/alignment of transforms, colors, id map, wall segments, the fixed-layout `vestibule` record, `shaft_colliders`, general `colliders` per doc 04 layouts) → implement emission
- [x] 3.6 Add `proptest` property tests: placement totality, uniqueness, in-bounds across fuzzed (seed, catalog size); vertical alignment (every floor-N+1 gallery's `(q, r)` matches an occupied floor-N gallery) holds under fuzzing too — found and fixed a real bug: unequal floor sizes broke vertical-neighbor index pairing (see `graph.rs` `floor_start_idx` fix)
- [x] 3.7 RED→GREEN: vitest tests against the real wasm build via the `web/src/wasm/` facade (buffer shapes for a 100-book catalog, immediate copy-out, no `any` at the boundary via `tsc --noEmit`; graph JSON includes `(q, r, floor)` + neighbor refs + the `config` constants block, and buffer lengths are consistent with `config.booksPerHex` — the frontend never hardcodes world numbers) → implement wasm-bindgen bindings + facade. Also required adding `getrandom`'s `wasm_js` backend (Cargo feature + `RUSTFLAGS` cfg, documented in `scripts/wasm-build.sh` and doc 08) since `rand` refuses to target `wasm32-unknown-unknown` otherwise, even with no OS-entropy calls in this crate.

- [x] 4.6 RED→GREEN: shaft-visibility test (a gallery with a generated floor-below counterpart shows that gallery through the shaft opening; a gallery with no floor-below shows none) → shaft-visible lightweight floor-above/below groups (doc 05 streaming). **Implemented after 4.8, out of tasks.md order** (see 4.8's note): a first attempt here failed honestly — every gallery was built fully at the time (no culling existed yet), so there was no real "not-yet-fully-loaded neighbor" state for the shaft-glimpse mechanism to serve, and the first e2e test passed for the wrong reason (it detected the always-present full gallery, not the lightweight glimpse). Reverted that attempt cleanly and did 4.8 first.

  With streaming's full/glimpse tiers in place, `GalleryStreamer.update()` now builds vertical (floor-above/below) neighbors via `buildShaftGlimpse` (`web/src/scene/shaft-visibility.ts` — floor/ceiling hex + shaft hole only, no shelves/books/vestibule) instead of the full architecture. Writing the real e2e test caught a genuine bug: the streamer upgraded glimpse→full when a gallery became the horizontal-adjacent "current" set, but never *downgraded* full→glimpse when a previously-current gallery dropped back to vertical-neighbor-only — it just stayed fully built forever, which would have silently blown the draw-call budget on any real multi-floor walkthrough. Fixed in `update()` (both upgrade and downgrade paths now handled symmetrically) and locked in with a dedicated unit test (`tests/streaming-streamer.test.ts`) plus 3 e2e tests (`e2e/shaft-visibility.spec.ts`, using the same `?e2eBookCount=` override from the reverted attempt, now put to its intended use) proving: glimpse exists for a real floor-below neighbor, no glimpse exists where there's no neighbor, and walking into a glimpse gallery upgrades it to a full build.
- [x] 4.7 Lighting + fog (exploratory, fixed 2-lamps-per-gallery per Borges) → acceptance test written when settled: screenshot-based luminance check that no traversable position renders fully dark, and no traversable position is brighter than the "insufficient, dim" intent (qualitative — spot-checked, not a hard threshold)

  Doc 05 already pinned exact values (not actually open-ended), so this was implemented directly rather than tuned live: `AmbientLight(0xfff2e0, 0.35)` + `FogExp2(0x14100c, 0.045)` scene-global (`web/src/scene/lighting.ts`), plus exactly `LAMPS_PER_HEX` (2) dim `PointLight(0xffd9a0, 8, 10, 2)`s per gallery at the lamp prop positions from `prop_transforms`, added/removed with each gallery's group by `GalleryStreamer`. First luminance-threshold test draft was too weak to prove anything: placeholder lamp fixtures are emissive (self-illuminating independent of scene lights), so an absolute "not pitch black" floor passed even with zero lighting code wired up. Fixed by testing the real signal — a `?e2e&noLighting=1` debug-only toggle disables ambient/fog, and the test asserts the normal boot is measurably brighter than that control (confirmed both a genuine RED with lighting disabled and GREEN restored) while staying under a "not brightly lit" ceiling.
- [x] 4.8 RED→GREEN: streaming test (crossing a vestibule opening: entered gallery already populated — no pop-in; crossing a staircase to a new floor: destination gallery already populated; two-hop gallery disposed in both horizontal and vertical directions; draw calls bounded) → gallery streaming + buffer cache, now covering horizontal + vertical adjacency. **Implemented before 4.6** (see 4.6 note) since it creates the not-fully-loaded-neighbor scenario 4.6's test needs to be meaningful.

  `web/src/scene/streaming.ts`: `neededGallerySet(galleries, currentIndex)` (pure, unit-tested in `tests/streaming.test.ts`) plus `GalleryStreamer` (builds missing groups, disposes groups no longer needed, keeps up to 4 disposed galleries' buffers cached so re-crossing is cheap — tested against the real wasm build with a 2500-book multi-floor catalog in `tests/streaming-streamer.test.ts`, and end-to-end in `e2e/streaming.spec.ts`). `main.ts` now calls `streamer.update(spawnGallery)` once at boot instead of eagerly building every generated gallery — this is what makes "draw calls bounded" real rather than aspirational. `debug.ts`'s hook gained `liveGalleryIndices()` and `setCurrentGallery(index)` (the latter is a minimal stand-in for doc 09's eventual full `teleport(q,r,floor,x,y,z,yaw)`, which needs the navigation/collision system from task 5.x — not built yet). Updated `vestibule-shaft.spec.ts`/`instancing.spec.ts` to iterate live galleries instead of assuming every generated gallery is always in the scene. Vertical-adjacency streaming is exercised by `neededGallerySet`'s unit tests and the wasm-backed `GalleryStreamer` tests (2500-book catalog forces real floor-above/below links); a real *floor-crossing* e2e walk (as opposed to direct `setCurrentGallery` calls) isn't possible yet without the staircase movement mode (task 5.3/5.4).
